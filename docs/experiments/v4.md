# Audio V4 실험 안내

V4는 3초 슬라이딩 윈도우마다 점수를 계산하고 녹음의 최대 점수를
`abnormal` 확률로 사용하는 파이프라인입니다.

Spring이 전송한 파일은 요청마다 독립적으로 처리됩니다. 3초 파일은 윈도우
하나로 한 번 추론하며, 더 긴 파일은 3초 윈도우를 1초 간격으로 나누어
추론합니다. 요청 사이의 오디오 상태는 서버에 보관하지 않습니다.

## 데이터와 라벨

기본 v4 학습은 ESC-50만 사용합니다. `audio_guard.labels.TARGET_CLASSES`에
포함된 기존 여섯 카테고리는 `abnormal=1`, 나머지는 `normal=0`입니다.
`door_wood_knock`은 노크 이벤트이므로 타깃에 유지합니다. 문고리 당김 등
현장 위험음은 기본 모델 학습 후 별도의 v4 fine-tuning 과정에서 추가합니다.

## 실행

```bash
python -m audio_guard.interfaces.cli.train_cli \
  --pipeline v4 \
  --esc50-dir data/ESC-50 \
  --model-out models/audio_model_v4.keras

python -m audio_guard.interfaces.cli.evaluate_cli \
  --pipeline v4 \
  --esc50-dir data/ESC-50 \
  --model models/audio_model_v4.keras
```

fold 1~3은 학습, fold 4는 threshold 선택, fold 5는 최종 평가에 사용합니다.
평가 후 모델 옆에 생성되는 `audio_model_v4.config.json`에는 선택된 threshold와
v4 런타임 설정이 저장됩니다.
현장 위험음 fine-tuning 절차는 [v4_finetune.md](v4_finetune.md)를 참고합니다.
